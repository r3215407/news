# 讯哨 · 新闻监控

Next.js 网页，监控 X 账号最近五条动态，只展示发布后 24 小时内的内容，并按 ID 跳过本次服务运行期间已播报的内容。

## 启动

```bash
npm install
npm run dev
```

打开 `http://127.0.0.1:3000`。页面会先恢复此浏览器保存的账号，再检查最新动态；未保存过账号时从默认账号 `@thsottiaux` 开始。之后页面打开期间每 60 秒检查一次；出现异常账号时，可用“重试异常”只重新获取这些账号。账号可在左侧添加或移除。

中文总览位于新闻列表上方，由用户点击“生成总览”后才通过 NVIDIA 的 `nvidia/nemotron-3.5-bolt-e4b` 生成。完全相同的动态会先合并，模型再将意思相近的内容压缩成一份总览，同一事实只叙述一次。发给模型的每条内容包含 `author`、`content` 和对应的 `sourceNumbers`；页面将引用编号映射为真实 X 链接，并在总览下提供全部原文链接，原文网址不发送给模型。总览按当前动态 ID 集合保存在浏览器 `localStorage` 中，刷新页面后仍可查看；已有总览可手动重新生成，列表变化后也可以生成新总览。新闻检查不会自动请求模型。在已创建的 `.env.local` 中填写 `NVIDIA_API_KEY`，然后重启 Next.js 服务；可选用 `NVIDIA_SUMMARY_MODEL` 指定其他兼容模型。没有密钥或摘要服务失败时，页面会直接提示错误，不保存结果；原文仍可查看。不会发送邮件。

监控账号列表保存在当前浏览器的 `localStorage` 中，刷新页面或重启服务后会自动恢复。首次加载会将当前服务中的账号迁移到浏览器。已播报 ID 和播报记录仍只保存在 Next.js 服务进程的内存中，重启后会从头播报；多个服务实例之间也不会共享播报状态。自动检查只在网页打开时运行。接口即使返回多于五条，服务端每次也只处理前五条，因此两次检查之间发布超过五条时，较早的动态可能被跳过。
